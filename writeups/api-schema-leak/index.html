A public API schema that gave away the back office

An unauthenticated endpoint on a financial-data platform served its whole API specification to anyone who asked — including the internal order-workflow and the names of settlement counterparties. It was a real exposure. It was also nine days too late.

What it was

The platform published its OpenAPI 3.0.3 specification at a schema endpoint that took no authentication: a plain unauthenticated GET returned the document with a 200. An API serving its own schema is ordinary and often deliberate. What made this one matter was the content. The spec was generated from the live back-end models, so it carried more than the public, customer-facing routes: it described the internal order-workflow state machine, and the schema definitions named the settlement counterparties the platform transacts with.

None of that is meant to be readable without an account. For a financial platform, the counterparty names alone are commercially sensitive, and the internal workflow is a map an attacker would otherwise have to infer endpoint by endpoint. The fix is small — scope schema generation to public routes, or put the endpoint behind the same auth as the API it documents — which is part of why it is an easy mistake to ship.

Why it is worth writing up anyway

Because of how it ended. I reported it through the platform's bug-bounty program, with authorization, and it was closed as a duplicate: another researcher had filed the same endpoint nine days earlier. No bounty, no credit — a duplicate pays nothing.

That outcome is the useful part. A duplicate is the one close that confirms the finding was real: an independent reporter saw the same issue and the program agreed it was one. The bug was sound. The miss was process. Before writing a report, the first move is deduplication — checking the program's disclosed reports, its public activity feed, and anything already indexed about the target — and I had not spent long enough on it. The analysis was right and the timing was wrong, and in bug bounty the timing is half the work.

What I changed

Dedup now comes before the write-up, not after submission: read the program's recent activity and any disclosed reports for the same asset first, and only invest in a full report once I am reasonably sure the finding is not already in flight. It costs a few minutes and it is the cheapest way to avoid writing up something that cannot pay.

The target stays unnamed here: the report was handled privately and was never publicly disclosed, so naming it would cross a line the duplicate outcome does not move.
